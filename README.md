# 마음 SIGNAL LAB

AI 시대에 사람의 마음을 이해하는 직업을 체험하는 **중학생용 진로교육 웹앱**입니다.
학생은 마음 SIGNAL LAB의 신입 청소년상담사가 되어 가상 사례를 탐색합니다.

> 디자인 시안을 **참조**해 실제 UI를 DOM/CSS로 새로 구현했습니다.
> 시안 이미지를 배경으로 깔거나 스크린샷 위에 투명 버튼을 얹는 방식은 사용하지 않습니다.
> 인물·배경 일러스트만 별도 이미지 에셋(`public/assets/`)으로 합성하고,
> 그 위의 UI·단서 핫스팟은 전부 DOM 요소입니다.

## 기술 스택

- **Next.js 16 (App Router)** + React 19 — Vercel에 그대로 배포 가능
- **CSS Modules** + `app/globals.css`의 디자인 토큰 (별도 CSS 프레임워크 없음)
- 본문 `next/font/google`의 Noto Sans KR, 제목 **에스코어드림(S-Core Dream)** —
  `public/fonts/` 에서 직접 서빙 ([왜 그렇게 했는지](public/fonts/README.md))
- 빌드 산출물은 정적 프리렌더(`○ Static`)

```bash
npm install
npm run dev     # http://localhost:3000
npm run build   # 프로덕션 빌드
```

## 현재 구현 범위

**사례 3개 × 7단계.** 학생 활동 기준 전체 약 75분으로, 2차시 수업 분량입니다.

### 사례

| CASE | 주인공 | 주제 | 배우는 것 |
| --- | --- | --- | --- |
| 01 | 민서 | 관계 · 소외감 | 관찰에서 시작해 AI가 단정한 문장을 걸러낸다 |
| 02 | 서현 | 죄책감 · 자기비난 | 잘못한 쪽으로 보였던 사람에게도 사정이 있다. 자기비난과 책임지기는 다르다 |
| 03 | 준호 | 온라인 소문 · AI 리터러시 | 캡처는 증거가 아니다. 위기 신호는 어른에게 연결한다 |

세 사례는 같은 사건을 세 사람의 자리에서 봅니다.
사례 데이터는 `lib/cases/` 에 파일 하나씩 들어 있고, `lib/cases/index.js`
의 배열에 추가하기만 하면 네 번째 사례도 붙습니다.

### 사례는 순서대로 하나씩 열린다

시작 화면(`screens/Title.jsx`)은 제목과 버튼 하나만 보여 줍니다. 사례 카드를
나열하지 않습니다. 버튼을 누르면 **아직 안 한 사례 중 가장 앞의 것**이 열리고,
그 사례의 07 결과 확인까지 가야 다음 사례가 열립니다.

완료 판정은 `app/page.jsx`의 `backToTitle`에 있습니다. `step === "result"` 일
때만 `done` 에 기록하므로, 중간에 나가면 다음 사례가 열리지 않습니다.

### 각 사례의 7단계

| 단계 | 화면 | 컴포넌트 | 내용 |
| --- | --- | --- | --- |
| 01 | **CASE 안내** | `screens/CaseIntro.jsx` | 좌: 사례 장면 · CASE 번호 배지 · 시그널 탐지율<br>우: 미션 헤드라인, 4개 미션 아이콘, 활동 미리보기 3카드, CTA "미션 시작하기" |
| 02 | **단서 탐색** | `screens/ClueHunt.jsx` | **정보원 3곳**에서 단서 6개. 장면(관찰형 핫스팟 3) · 기록(서류 카드 2) · 이야기(증언 카드 1). 단서 상세(관찰/인사이트/출처), 출처별 수집 목록, 힌트 |
| 03 | **상담 대화** | `screens/Counseling.jsx` | 메신저형 UI, 3턴 선택지 대화, 반응 품질 피드백(좋은/무난한/아쉬운), 공감 점수 |
| 04 | **AI 리포트 검토** | `screens/AiReport.jsx` | AI가 쓴 8문장을 **사실 / 추론 / 더 확인**으로 분류. 문장마다 왜 그런지 피드백, 검토 진행률 |
| 05 | **새로운 메시지** | `screens/NewMessage.jsx` | 판단을 끝낸 뒤 도착하는 반전. 기존 문장 4개를 **그대로 / 흔들림**으로 다시 판단 |
| 06 | **상담 전략** | `screens/Strategy.jsx` | 도움 카드 6장을 **오늘 바로 / 이번 주 안에 / 어른과 함께** 슬롯에 배치해 상담 계획표 완성 |
| 07 | **결과 확인** | `screens/Result.jsx` | 5개 역량 원형 게이지 + 관련 진로 카드 4장. 점수는 전부 실제 플레이 기록에서 계산 |
| — | **탐색 노트** | `screens/NoteDrawer.jsx` | 모은 단서 + 상담 기록을 모아 보는 우측 드로어 |
| — | **시작 화면** | `screens/Title.jsx` | 제목만 있는 랜딩. 버튼 하나로 «아직 안 한 사례»가 열린다 (사례 목록을 펼치지 않음) |
| — | **사례 장면** | `scene/CaseScene.jsx` | 배경 이미지 위에 인물 컷아웃을 % 좌표로 합성. 단서 핫스팟도 같은 % 좌표계라 패널 비율이 바뀌어도 어긋나지 않음 |

> 참고: 단계 네비게이션의 `03 시그널 분석`에 상담 대화 화면이 들어갑니다.
> (대화를 통해 시그널을 수집 → 정리하는 흐름)

### 02 단서는 세 곳에서 나온다

처음에는 단서 5개를 전부 그림 한 장에서 찾게 했습니다. 그런데 «어제까지
달려 있던 키링», «이번 주에만 세 번째», «알림이 계속 울린다» 같은 것은
정지된 그림으로는 알 수 없습니다. **없는 것을 찾으라고 시킨 셈**이라
아무리 들여다봐도 못 찾는 게 당연했습니다.

그래서 단서마다 출처를 나눴습니다 (`lib/shared.js`의 `CLUE_SOURCES`).

| 출처 | 어떻게 얻나 | 얼마나 믿나 |
| --- | --- | --- |
| **장면** | 그림을 관찰해 직접 찾는다 (사례당 3개) | 내가 봤으니 사실. 다만 이유는 모름 |
| **기록** | 출결부·상담 접수 대장 같은 서류를 연다 (2개) | 숫자는 사실. 이유는 아직 아님 |
| **이야기** | 짝꿍·담임에게 듣는다 (1개) | 사실이 아니라 **확인할 것** |

출처가 다르면 믿는 방식도 달라야 한다 — 이게 04 AI 리포트에서 사실·추론·
더 확인을 가르는 연습의 밑그림입니다. 모은 단서에는 출처 꼬리표가 붙어
탐색 노트까지 따라갑니다.

> **장면 단서만은 표시가 없습니다.** 관찰해서 직접 찾아야 하기 때문입니다.
> 30초 동안 못 찾거나 학생이 «손전등 비추기»를 누르면, 남은 단서 하나에
> 손전등 빛이 3.8초간 떨어집니다. (`ClueHunt.jsx`의 `IDLE_MS` · `TORCH_MS`)
>
> 장면 단서는 **그림에 실제로 그려진 것만** 씁니다. 새 사례를 만들 때도
> 이 규칙을 지켜 주세요. 그리지 않은 것을 단서로 쓰면 학생은 못 찾습니다.

> 05 새로운 메시지의 핵심은 «새 정보는 사실을 지우지 않지만 추측은 흔든다»입니다.
> 04에서 사실/추론을 나눈 경험을 한 번 더 뒤집어 확인하게 합니다.

### 역량 점수 계산 (`app/page.jsx`)

결과 화면의 게이지는 임의의 값이 아니라 플레이 기록에서 나옵니다. 사례마다 따로 계산됩니다.

| 역량 | 계산 |
| --- | --- |
| 공감력 | 대화 선택지 점수 합 ÷ 만점(60) |
| 관찰력 | 찾은 단서 수 ÷ 전체 단서 수 |
| 질문력 | 선택지 품질 평균 (좋은 100 / 무난 65 / 아쉬운 30) |
| 판단력 | (추천 시점과 일치한 도움 카드 ÷ 6, 다시 판단 정답 ÷ 4)의 평균 |
| AI 리터러시 | 정확히 분류한 리포트 문장 수 ÷ 8 |

## 반응형

- `≥1081px` — 사이드바 고정 + 2단 카드 레이아웃
- `≤1080px` — 사이드바가 햄버거 드로어로 전환, 카드가 세로 스택
- `≤620px` — 모바일 최적화(설명 문구 축약, 액션 버튼 세로 배치)
- 단서 핫스팟과 인물 위치가 모두 장면 대비 %라, 패널 비율이 바뀌어도 서로 어긋나지 않음
- 하단 단계 네비게이션은 `≤1360px`에서 현재 단계만 라벨을 남기고 나머지는 번호로 축약

## 교육 원칙

- 실제 심리진단을 하지 않습니다.
- 모든 사례는 가상 직업체험용입니다.
- 학생의 실제 우울·불안 등을 점수화하지 않습니다.
- 결과는 상담사 직무역량 학습 결과로만 보여줍니다.
- AI의 답변을 그대로 믿기보다 사실·추론·추가 확인 필요 정보를 구분하도록 설계합니다.

## 이미지 에셋

인물·배경·진로 카드 일러스트는 `public/assets/` 아래에 들어갑니다.

- **필요한 파일 목록과 현재 상태** → [`public/assets/README.md`](public/assets/README.md)
- **생성용 프롬프트** → [`public/assets/PROMPTS.md`](public/assets/PROMPTS.md)

`components/ui/AssetImage.jsx`가 확장자 없는 경로를 받아
**`.webp` → `.png` → 그라디언트 플레이스홀더** 순으로 시도합니다.
덕분에 아직 없는 에셋 자리에도 깨진 이미지가 뜨지 않고, 파일을 규약대로
올리면 코드 수정 없이 표시됩니다. 리포에는 용량 때문에 WebP로 커밋합니다
(생성 원본 PNG 2.2MB → 0.17MB, 육안 차이 없음).

이 단계에서는 로그인, 데이터베이스, 실제 AI API 호출을 넣지 않았습니다.
